# 软件部署与打包说明（防遗忘）

> 适用工程：`daq_tablet`（伽马能谱探测 / 通道 DAQ 平板）  
> 整理日期：2026-07-27

---

## 1. 先分清两件事

| 交付物 | 管什么 | 能用在哪 |
|--------|--------|----------|
| **SD 卡系统镜像** | 整机 OS + 驱动 + RTC/NTP + 网络 + 软件 | 基本只限 **同型号树莓派 5** |
| **软件安装包** | 只有 `daq_tablet` 程序 | **同 CPU 架构** 的 Linux 工控机 / Pi / Windows |

- 镜像：**量产同款 Pi 5 终端** 用。  
- 安装包：**任意电脑 / 工控 Linux 单板** 部署程序用。  
- **一张 Pi 镜像不能当“任意单板机系统盘”用。**

---

## 2. 树莓派 5 时间系统（已调通状态）

推荐状态：

```text
System clock synchronized: yes
NTP service: active
RTC in local TZ: no
```

含义：

- RTC 存 **UTC**（工业推荐）  
- 系统按本地时区显示  
- 断电靠 RTC 电池保时；联网后 NTP 自动校准  

验收（建议做一次即可）：

```bash
sudo hwclock -r
date
timedatectl
```

断电拔电 5～10 分钟再上电，若时间连续 → RTC 电池正常。

## 3. 镜像备份能干什么、不能干什么

### 能

- 备份当前 Pi 5 整机环境  
- 换卡 / 再做一台 **同款 Pi 5**，软件环境基本一致  

### 不能 / 要注意

| 项目 | 说明 |
|------|------|
| 换到 Pi4 / 香橙派 / 其他工控板 | ? 镜像一般无法启动 |
| 多台同镜像同静态 IP | 会冲突（如都是 `192.168.0.201`） |
| 主机名相同 | 局域网可能冲突 |
| RTC 电池 | 镜像不含电池，新板要自带电池并验收 |
| 文件系统扩容 | 大卡克隆后可能要扩展分区 |

**结论：** 镜像适合 Pi5?Pi5；不是通用安装盘。

---

## 4. 任意工控 Linux 单板怎么部署？

板子自带 Linux → 只装你的软件包（按架构）：

| 架构 | 典型设备 | 包名示例 |
|------|----------|----------|
| `aarch64` | 树莓派 5、多数 ARM 工控板 | `daq_tablet_linux_aarch64.tar.gz` |
| `x86_64` | 多数 x86 工控盒 | `daq_tablet_linux_x86_64.tar.gz` |

口诀：**在哪种 CPU 上打包，就给哪种 CPU 用。**  
Windows 上打的 exe **不能**给 Linux 单板用。

## 5. 一键打包怎么做（学习步骤）

工程目录：

```text
daq_tablet/packaging/
  daq_tablet.spec      # PyInstaller 配置
  build_linux.sh       # Linux 打包
  build_windows.bat    # Windows 打包
  install.sh           # 目标机安装
```

### 5.1 Linux（Pi / 工控机）

在**与目标机相同架构**的 Linux 上：

```bash
cd /path/to/daq_tablet/packaging
chmod +x build_linux.sh install.sh
./build_linux.sh
```

产物示例：

```text
packaging/dist/daq_tablet_linux_aarch64.tar.gz
```

拷到目标机：

```bash
tar -xzvf daq_tablet_linux_aarch64.tar.gz
cd daq_tablet
sudo ./install.sh
daq_tablet
```

默认安装到：`/opt/daq_tablet`  
并创建桌面快捷方式、`/usr/local/bin/daq_tablet`。

### 5.2 Windows（售后笔记本）

双击：

```text
packaging\build_windows.bat
```

产物：`packaging\dist\daq_tablet\`  
整夹拷走，双击 `daq_tablet.exe`。

## 6. 推荐产品交付组合

```text
量产树莓派5通道机  ──? SD 整机镜像（含 OS + 软件 + RTC + 网络）
任意 Linux 工控板  ──? 对应架构 tar.gz + install.sh
Windows 调试/售后  ──? dist\daq_tablet 文件夹（exe）
```

## 7. 与现有自启的关系

工程里已有：

- `spectrometer.service`  
- `start_spectrometer_rpi.sh` 等  

若改用打包后的程序自启，把 service 里的 `ExecStart` 改成例如：

```text
ExecStart=/opt/daq_tablet/daq_tablet
```

（路径以 `install.sh` 实际安装位置为准。）

占用/报警等业务仍在现有 `daq_tablet` 工程内，**不必**再新建独立的 `/home/raysen/detect/` 工程（除非改成 Pi 直读 GPIO 的另一条产品线）。

## 8. 常见坑

1. **跨架构混用包** → 必挂（x86 包不能给 ARM）。  
2. **打包机系统比目标机新太多** → 可能 `GLIBC_xxx not found`。尽量用相近 Ubuntu 版本打包。  
3. **无桌面的纯服务器** → PyQt 界面跑不起来。  
4. **串口权限** → 用户需在 `dialout` 组，装完可注销重登。  
5. **打包失败看不到错** → 把 `daq_tablet.spec` 里 `console=False` 临时改成 `True`。  
6. **gpiozero / opencv** → 当前占用走 MCU `device_status bit5` 时**不必**为部署而强装；Pi 直读 E3Z 时再考虑 gpiozero。  
7. **Windows 只拷了 exe** → 弹窗 `Failed to load Python DLL '...\_internal\python314.dll'` / `找不到指定的模块`。  
   这是目录模式打包：`daq_tablet.exe` 必须和 `_internal` 文件夹在同一层。把整个 `dist\daq_tablet` 文件夹拷走再双击 exe。  
   若文件夹完整仍报此错：安装 [VC++ 2015-2022 x64 运行库](https://aka.ms/vs/17/release/vc_redist.x64.exe)，并用 `build_windows.bat` 重新打包（已关闭 UPX）。

---

## 9. 建议练习顺序

1. 当前 Pi 上跑通 `./packaging/build_linux.sh`  
2. 不解压源码，只跑打包出的 `./daq_tablet`  
3. `sudo ./install.sh`，从菜单启动  
4. 有 x86 工控机时，再打 `x86_64` 包  
5. （可选）改 systemd 指向 `/opt/daq_tablet/daq_tablet`  

---

## 10. 一句话记住

> **镜像 = 整机克隆（基本只限 Pi5）；软件包 = 同架构一键装程序（工控 Linux / Windows）。**  
> **打包必须在同架构机器上做；应用可移植，系统镜像不可跨板通用。**
